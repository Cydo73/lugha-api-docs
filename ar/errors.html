الأخطاء¶

عندما يفشل طلب ما، يكون جسم الاستجابة دائمًا بالهيكل نفسه، بغض النظر عن سبب الخطأ.

{
  "error": {
    "type": "invalid_request",
    "message": "model: Field required",
    "request_id": "req_502924837fc6"
  }
}
type

فئة يمكن للآلة قراءتها. استخدم هذه القيمة لتحديد مسار التعليمات البرمجية.

message

شرح بسيط للبشر. اعرضه في السجلات، ولكن لا تحلله برمجيًا. قد تتغير صياغته.

request_id

معرّف هذا الطلب. يوجد أيضًا في ترويسة الاستجابة X-Request-ID. اذكره عند التواصل مع الدعم، ولا ترسل مفتاح API الخاص بك أبدًا.

أنواع الأخطاء¶

type

الحالة

ما يعنيه

إعادة المحاولة؟

authentication_required

401

ترويسة Authorization مفقودة أو غير صحيحة.

لا

invalid_api_key

401

لم يتم التعرّف على المفتاح.

لا

invalid_request

400

هناك حقل مفقود أو يحتوي على قيمة غير صحيحة. تحدد الرسالة الحقل المعني.

لا

unsupported_language

400

النموذج لا يدعم هذه اللغة. تسرد الرسالة اللغات التي يدعمها.

لا

unsupported_region

400

المنطقة ليست واحدة من ke أو ug أو ma أو mu.

لا

model_not_found

404

لا يوجد نموذج بهذا المعرّف. اعرض قائمة النماذج باستخدام GET /v1/models.

لا

not_found

404

لا توجد نقطة نهاية على هذا المسار.

لا

method_not_allowed

405

نقطة النهاية لا تقبل طريقة HTTP هذه.

لا

rate_limit_exceeded

429

لقد استهلكت جميع طلباتك لهذا الدقيقة.

نعم، بعد Retry-After

internal_error

500

حدث خطأ ما من جانب الخدمة.

نعم، مع تأخير متزايد

يعني 400 أو 401 أو 404 أو 405 أن الطلب نفسه يحتاج إلى التغيير. ستؤدي إعادة إرساله دون تغيير إلى الفشل مرة أخرى.

أمثلة¶

نموذج لا يدعم اللغة التي طلبتها:

{
  "error": {
    "type": "unsupported_language",
    "message": "Model 'lugha-demo-small' does not support language 'am'. Supported: en, sw, lg.",
    "request_id": "req_183e64b5682b"
  }
}

الحل موجود في الرسالة. استخدم نموذجًا يدعم اللغة، أو اختر إحدى اللغات المذكورة.

حدود معدل الطلبات¶

يمكن لكل مفتاح API إجراء 10 طلبات في الدقيقة. يُعاد ضبط العدد في بداية كل دقيقة. تخبرك كل استجابة بحالة استخدامك.

الترويسة

المعنى

X-RateLimit-Limit

عدد الطلبات المسموح بها في الدقيقة.

X-RateLimit-Remaining

عدد الطلبات المتبقية في الدقيقة الحالية.

X-RateLimit-Reset

عدد الثواني حتى يُعاد ضبط العدد.

عند استهلاك جميع طلباتك، يعيد الطلب التالي الحالة 429 مع ترويسة Retry-After.

HTTP/1.1 429 Too Many Requests
Retry-After: 60
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 60
X-Request-ID: req_658e47454555

{
  "error": {
    "type": "rate_limit_exceeded",
    "message": "You have used all 10 requests for this minute. Retry in 60 seconds.",
    "request_id": "req_658e47454555"
  }
}

انتظر عدد الثواني المحدد في Retry-After، ثم أرسل الطلب مرة أخرى. إعادة المحاولة فورًا تستهلك فقط المزيد من حصتك المسموح بها.

إذا رأيت 429 بشكل متكرر، فخفّض سرعة طلباتك. راقب X-RateLimit-Remaining وتوقف مؤقتًا قبل أن يصل إلى الصفر.

ما يجب إعادة المحاولة بشأنه¶

أعد محاولة 429 بعد التأخير المحدد في Retry-After. أعد محاولة 500 وأخطاء الشبكة باستخدام تأخير أُسّي، أي الانتظار لفترة أطول قليلًا بعد كل محاولة فاشلة. لا تعاود محاولة الأخطاء الأخرى أبدًا.

تتضمن قائمة التحقق الخاصة ببيئة الإنتاج عميلًا ينفذ كل ذلك.
